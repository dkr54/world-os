本卡功能包

把回复中的总结变成长期记忆。每条模型回复及其前面的用户消息算一楼。

更早 K 楼召回→中间 M 楼总结→最近 N 楼原文

中间总结和历史召回均保留对应楼层的用户消息，仅替换模型回复。尚未得到回复的用户消息始终保留。续写时至少保留正在续写的一楼。K 是召回上限。

① 正则：先清洗，再提取

规则按列表顺序执行，只处理提取用的副本。最近 N 楼原文不受这些规则影响。支持 JavaScript 正则、替换中的 $1 和 /pattern/flags 写法。

默认提取 <summary>…</summary> 的第 1 组；可改成你的总结标签。多个匹配以空行连接。0 表示完整匹配。

          ② 关键词优先
          
          
          
从最新第 1 条用户消息往上，取到第 D 条用户消息，包含两者之间的全部模型回复。D=2 即“上条用户消息 → 中间模型回复 → 最新用户消息”；D=0 只取尚未得到回复的用户消息。

          
匹配每楼已设置的触发关键词（手动或 AI 生成），任意一个词命中即可候选。从最近的命中楼层往前选，最多 K 楼，不按命中词数量排序。满 K 楼后不请求向量或重排；不足时由未命中的旧楼层补足。空关键词不参与关键词匹配。

完成地址和密钥输入后自动拉取，也可以点击刷新。使用当前表单内容，无需先保存；本地免密接口可留空密钥。

          
          
接口返回的列表可能包含聊天模型，请选择支持 Embedding 的模型。

支持 Cohere / Jina 格式的 /rerank 接口。填写完整地址或带版本的 API 根地址；服务需允许页面跨域访问。
