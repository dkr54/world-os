# world os · 世界操作系统

一个同时适用于 SillyTavern 和 TauriTavern（重点适配 Android）的前端扩展，以手机应用式首页组织内置功能。内置「角色目录」「日历」「状态快照」「实验室」和完整的「楼层记忆」。日历支持自定义历法、节日与推进时间；楼层记忆提取模型回复中已经存在的总结，按聊天保存，再用「更早的召回总结 → 中间 M 楼总结 → 最近 N 楼原文」构建发送给模型的聊天上下文。

当前版本 **1.2.0**。项目名称为 **world os**，安装地址统一使用 https://github.com/dkr54/world-os 。示例使用虚构占位角色；本次更新角色匹配标识和 CG 图片包，移除关系图谱。

不会额外调用聊天模型生成总结。向量化使用插件独立配置的、兼容 OpenAI Embeddings 格式的接口。可选的 AI 关键词功能使用另一套独立聊天接口，只从已有总结提取触发词。

## 通过 GitHub 链接安装

在 SillyTavern 或 TauriTavern 的 **扩展 → 安装扩展 / Install Extension** 中粘贴：

```text
https://github.com/dkr54/world-os
```

1. 确认安装，完成后重新加载页面／应用。
2. 点击首页／聊天页边缘的 **world os** 悬浮入口，再点击书本图标下的 **楼层记忆**，设置正则、N/M/K 和所需的模型接口，点击「保存设置」。
3. 打开「启用 world os」总开关；楼层记忆在自己的功能页独立启用，日历仍保留自己的规则开关。
4. 以后在扩展管理中检查并更新本插件，重新加载后使用新版本。

仓库的默认分支是 `main`，`manifest.json` 和运行文件直接位于仓库根目录，可由宿主正常克隆和更新。支持通过仓库链接安装；GitHub 发布不会自动把插件加入 SillyTavern 的官方资源列表。宿主入口见 [SillyTavern 第三方扩展安装说明](https://docs.sillytavern.app/extensions/#third-party-extensions)。

如果提示同名扩展已存在，可先导出总结，再在扩展管理中移除旧的手动安装版本，随后使用上面的仓库链接安装。

离线安装包见 [版本发布页](https://github.com/dkr54/world-os/releases)：普通扩展 ZIP 用于手动复制，TauriTavern ZIP 用于手机「数据迁移」导入。仓库维护和后续上传方法见 [发布与更新说明](https://github.com/dkr54/world-os/blob/main/PUBLISHING.md)。

- 移除角色关系图谱、关系页和相应底部入口；底部保留「角色」「接口」「调试」。已有关系状态、状态更新权限和 `{{relationship.角色名}}` 宏继续可用。

## 1.1.1 修复：禁用旧安装后仍可能重复处理提示词

部分 TauriTavern 版本在分发生成处理入口时仍会遍历已禁用扩展的安装清单。旧安装与新安装都声明 floorMemoryInterceptor 时，即使只启用新版，同一份提示词也可能被新版处理两次；第二次可能报“无法可靠对应本次提示词与聊天楼层”。

本版按同一次生成、聊天和请求数组去重，重叠调用共用正在进行的处理，避免重复压缩和重复请求向量。下一次生成仍会正常重新处理；真正无法对应楼层时保留原有暂停保护，修正后可重试。

更新当前启用的 world os 至 1.1.1 后，完全关闭并重新打开 TauriTavern。旧安装保持禁用即可；若同时启用两份，请只启用新版。无需提供聊天正文，也无需修改正则、预设或 N/M/K。

## 1.1.0 更新：实验室

首页新增烧瓶图标「实验室」，可导入用户开发的独立功能页。包支持 .worldos.json 和 ZIP，包含清单、HTML、CSS、普通 JavaScript 和包内图片。开发格式、SDK 与示例见 [功能包开发说明](docs/LABORATORY.md)。

- **全局导入，按角色卡启用**：导入后所有角色卡的实验室都能看到它；默认关闭，开启后在首页「本卡功能包」显示图标。同一卡的各聊天共享开关与包配置。
- 包可保存当前聊天的独立状态。切换卡、切换聊天、返回首页、关闭窗口或关闭 world os 后，旧页面会停止；不会后台常驻。
- 导入先预览名称、版本和权限，再确认；同 ID 更新保留配置和数据，新增权限需要重新启用。全局卸载移除代码与入口，保留原数据。
- 功能页使用独立沙盒，通过 SDK 读写自己的配置与状态；声明权限后可读取最近聊天，或向输入框前置/追加文字，不会直接发送聊天。
- 提供「下载示例笔记包」，导入并开启后可体验同一卡共享标题、各聊天独立笔记。也可直接使用仓库中的 [示例包](examples/notes.worldos.json)。
- 实验室包与数据包含在状态快照中，兼容旧快照；快照的 32 MB 限制保持不变。恢复后需手动打开包页面才执行。
- 包内脚本需可信；当前不提供直接外网访问、后台自动运行或模型请求接口。「微博」仍处于可行性讨论阶段，未实现。

使用路径：**world os → 实验室 → 导入功能包 → 确认全局导入 → 在当前角色卡启用 → 首页打开图标**。包配置可在「本卡配置」编辑 JSON；功能页也能提供自己的设置界面。

## 角色 CG 图片包、Token 计数与默认状态模板

- 「新建角色」旁新增「默认状态」，可编辑当前角色卡共享的新角色基础状态 JSON 模板，支持空对象、内置模板重填和格式校验。每个新角色获得独立副本；保存模板不修改已有角色或当前聊天状态。
- 角色详情底部「当前阶段与宏替换预览」显示 **上下文 Token**。统计已保存基础设定、当前匹配阶段、状态宏及角色包裹标签；使用宿主当前分词器，不额外请求角色状态模型。预览、状态或阶段变化后重新统计，提供「重新统计」按钮。数字表示该角色被召回时这段文本的大小，不包含独立的 CG 清单、其他提示词或整个请求的封装开销；宿主分词器本身可能回退估算，暂时不可用时不会伪造为 0。
- 每个目录角色新增数字 **ID**，在所属角色卡下从 **0** 自动递增，保存后固定，删除后不自动复用。旧角色首次载入自动补号，原有聊天状态继续对应原角色。允许同名角色，列表显示 ID，CG 通过 ID 定位。
- 每个角色详情提供「角色 CG 图片包」，支持新建／移除图片包、命名、批量上传、添加 HTTP(S) 图片地址、移除包内单张图片，以及复制图片包宏。编辑后点击「保存角色设定」。
- 在聊天预设中写入 **`{{CG}}`**，它将列出本轮命中角色的全部图片包宏；没有 CG 的角色不输出空块。`{{character}}` 仍负责角色设定。
- CG 仅替换聊天显示，不改聊天消息、swipe 文本或编辑器内容，也不会将图片 URL／Base64 放进模型提示词。
- 角色列表上方「聊天 CG 显示范围」设置 **只显示最近 N 楼**，修改立即保存，所有角色卡共用。默认 **10**，范围 **0～1000**，**0 关闭图片显示**。用户和 AI 各一条消息算一楼，跳过系统／工具消息。超出 N 楼立即移除图片元素并恢复宏文字，不把图片一直藏在 DOM 中。增大 N、重新打开聊天或重绘楼层后重新判断范围。
- 支持流式回复、消息编辑、移动端聊天节点重用和卡片切换；完整宏出现后才显示图片。找不到图片或加载失败时保留宏文字。
- 数字 ID、CG 列表、已上传图片、显示范围与默认状态模板均包含在 world os 状态快照中；兼容旧版无 CG 的快照。

例如角色「示例角色甲」ID 为 0，图片包名为「晨光」「重逢」，角色「苏岚」ID 为 1，图片包名为「日常」。每个包可有多张图片，两人本轮都被命中时，`{{CG}}` 展开为：

~~~text
<0_示例角色甲>
{{0.晨光}}
{{0.重逢}}
</0_示例角色甲>

<1_苏岚>
{{1.日常}}
</1_苏岚>
~~~

可以在预设中写：

~~~text
以下是本轮可用的角色 CG 图片包：
{{CG}}
在适合展示画面的地方，原样输出对应图片包宏。仅使用清单中的宏，不编造包名。
~~~

例如 AI 输出 `她推开窗，晨光洒入房间。{{0.晨光}}`，最近 N 楼内的显示区域会随机出现「晨光」包内的一张图片；点击编辑时仍看到 `{{0.晨光}}`。同一段消息可使用多个包宏，同一楼的同一个包重复出现时保持同一张图片。包名按原样区分大小写，可含中文、空格和点号，但不能含花括号、尖括号、换行或首尾空格。同一个角色的包名必须唯一，且不能占用已保留的旧图片宏名。手动改包名后旧聊天文字不会自动改写。

手机上传支持 PNG、JPEG、WebP、GIF，文件上限 12 MB。可直接嵌入的小图片保留原文件；较大静态图片自动缩小并保存成 WebP，避免设置文件过大。GIF 要保留动画需小于约 1.4 MB，较大的动图可使用图片地址。已经上传的图片随插件设置／快照保存，不依赖手机文件路径；外部 URL 的可用性仍取决于网络。批量保存大量 CG 时注意快照的 32 MB 导入上限。

同名角色的 CG 始终按数字 ID 区分；普通角色设定只在遇到重名时使用 ID 前缀区分标签。relationship 仍按姓名描述关系，可继续在设定中调用相应状态宏。

## 使用角色目录

1. 打开一张角色卡的聊天，进入 **world os → 角色目录 → 新建角色**。
2. 输入角色名、触发关键词、基础设定。图片可输入 HTTP(S) 地址，也可从手机选择 PNG/JPEG/WebP/GIF；上传图片会缩到最长边 512 像素后嵌入设置，便于随快照迁移。
3. 关键词用**英文逗号**分隔；中文逗号保留在词内。为空或关闭“参与关键词匹配”时不召回这个角色。
4. 在宿主聊天预设中创建并启用一条消息，在你希望放入角色设定的位置填写 `{{character}}`。使用宿主正常的宏替换接口，不需要把整段状态 JSON 放进预设。
5. 如需动态状态，编辑该角色的“基础状态与 AI 修改权限”，并在“接口”页填写独立服务地址、密钥、选择模型，再保存接口与预设。可以先测试；测试不会修改真实聊天。
6. 使用自动更新时勾选“每次真实 AI 回复后，自动更新本轮实际调用的角色”。手动更新在角色详情的“当前聊天的角色状态”内，可附加本次要求。
7. “调试”页显示最终上下文中实际调用的角色、查询文本、真实回复、上一轮与当前完整状态、字段差异和被忽略指令的理由。

### 角色查询范围

直接取准备生成时**最新的两条实际用户／AI 聊天消息**，不足两条就全部取用。系统消息、工具返回和工具调用占位不作为角色查询消息。这里不使用楼层记忆的“按模型回复计楼”规则，也不压缩查询文本。

例如，准备生成 ai_2 时已有 `user_0、ai_1、user_1`，取 `ai_1、user_1`。如果当前已有 `ai_0、user_0`，就取这两条。重新生成 swipe 时不把正在替换的旧回复作为查询。命中任意一个关键词即可加入角色；空关键词不匹配，也不使用向量查找角色。

### 角色查询清洗

打开 **world os → 角色目录 → 调试 → 查询文本正则清洗**，填写「匹配正则」「flags」「替换为」，然后点击「保存查询清洗」。规则全局保存，只影响角色目录的关键词查询；不修改聊天原文，也不与楼层记忆的正则设置联动。未配置时仍按原文匹配。

例如，删除完整的 `<thinking>…</thinking>` 或 `<think>…</think>` 段落，可填写：

~~~regex
<(thinking|think)\b[^>]*>[\s\S]*?<\/\1>
~~~

flags 填 `gi`，替换文本留空。正则也支持 `/pattern/flags` 写法，替换文本支持 `$1` 等捕获组；要清除前端内容，请按实际包裹标签追加匹配分支。不要只删除标签本身，否则内部人名仍会参与匹配。

「预览当前查询（已保存规则）」显示最近两条消息清洗后的实际查询，尚未保存的草稿不会用于预览。生成时先等待后台清洗完成，再展开角色设定和 CG 宏；两者使用相同的命中角色。调试记录中的自动匹配查询也使用清洗后的文本。清洗后没有正文时不命中任何角色；把匹配正则清空并保存即可恢复原文匹配。

保存时校验正则语法，执行沿用可终止的后台 Worker，兼容 TauriTavern Android 模式。执行失败或超时时显示原因，并跳过本次角色注入，不回退到未清洗原文。该功能不调用 AI 或新增网络请求；同一查询与规则复用清洗结果。规则包含在状态快照中，旧快照仍可导入。

### 新角色的默认状态

角色列表中的「默认状态」与「新建角色」并排。点开后编辑 JSON，点击「保存默认状态」，以后在这张角色卡下新建的角色会自动填入该模板。模板由同一卡的所有聊天共享，不同角色卡各自保存；新角色的状态是独立副本，仍可在详情页继续调整。

允许添加或删除任意受支持的状态字段，也允许空对象 `{}`。例如：

~~~json
{
  "age": 20,
  "affection": 0,
  "mood": "平静",
  "relationship": []
}
~~~

「填入内置模板」只改编辑框，点击保存才生效。模板不会覆盖已有角色的基础状态或聊天中的当前状态；这些仍需分别在角色详情中修改。默认模板自动包含在状态快照中。

### 状态宏与阶段

基础状态示例：

~~~json
{
  "age": 20,
  "heigh": "165cm",
  "affection": 30,
  "relationship": [
    {"苏岚": "初识"},
    {"青禾": "同行伙伴"}
  ]
}
~~~

基础设定可以写：

~~~text
示例角色甲，年龄 {{age}}，身高 {{heigh}}。
她与苏岚的关系是：{{relationship.苏岚}}。
~~~

这样年龄、身高和与苏岚的关系被替换进去，但未引用的 affection 及与青禾的关系不会自动发送。

每阶段可添加多条条件，支持数值比较、等于／不等于、文本包含、字段存在／不存在。所有条件同时满足才可选，**多个阶段满足时采用列表最靠后的一个**。基础设定始终保留，再追加该阶段设定；没有符合阶段时只使用基础设定。空条件阶段可以放在列表前面作为默认阶段。

例如“熟悉”阶段使用 affection >= 30，“信赖”阶段使用 affection >= 70，并把“信赖”放在后面。数值状态和比较值都需使用 JSON 数字（如 70），而不是字符串 "70"。阶段只是决定发送哪段设定，不会隐藏编辑器中的其他阶段。缺失的状态宏替换为空文本。

### 严格操作权限

- 无单独权限配置的**已有具体字段**默认只允许 update；状态类型不能被模型改变，例如数字 20 不能改成字符串 "20"。
- add 必须显式授权，字段必须尚不存在，值需满足配置类型。
- delete 必须显式授权，字段必须已存在，且指令不应携带 value。
- 不允许用 update 整体覆盖对象／数组来绕过子字段权限；修改其具体字段，例如 profile.age、traits.0。数组只允许更新已有元素。
- 关系状态始终使用对象数组保存；模型通过 `relationship.苏岚` 修改一条关系。可用 `relationship.*` 为关系条目配置通配权限，例如允许新增关系，同时禁止删除。
- 可以取消某字段的全部操作权限，使 AI 完全不能修改。用户手动编辑当前状态 JSON 不受这些 AI 权限限制。
- 模型仅能操作本次请求中的 characterId。不能用返回值修改角色设定、阶段或权限；不认识的操作名、额外指令字段、错误路径、重复修改、类型不符等会被忽略。
- 在模型请求过程中切换聊天、手动修改状态、更改设定／权限或关闭总开关，会使旧结果取消。保存失败时保留原有状态。

默认请求的返回结构如下，模型不必对每个角色都返回一项；没有变化就返回空 operations：

~~~json
{
  "operations": [
    {"op": "update", "characterId": "输入提供的角色id", "path": "affection", "value": 45},
    {"op": "add", "characterId": "输入提供的角色id", "path": "relationship.青禾", "value": "同行伙伴"},
    {"op": "delete", "characterId": "输入提供的角色id", "path": "temporaryMood"}
  ]
}
~~~

上述 add/delete 仅为格式示例，没有明确授权时会被忽略。JSON 的多余闭括号等可修复格式问题沿用本地解析器处理；程序不会推测缺失指令，也不会因为格式错误自动追加模型请求。

状态预设支持 `{{characters}}`、`{{query}}`、`{{reply}}`、`{{requirements}}`，分别表示允许更新的角色数据、生成前查询、真实回复和手动要求。程序始终保留输出结构约束与写入校验。模型列表使用 /models，状态更新使用 /chat/completions；接口必须允许当前宿主访问。默认“自动”思考模式对硅基流动 Qwen3-8B 发送 enable_thinking:false，可在界面调整。

### 保存范围

目录存于 `world_os_characters.cards`，按宿主角色头像文件名区分（群聊用群 ID）。这是与日历一致的角色卡关联方式；单独导出 PNG 角色卡不会包含这些插件设置，应同时导出 world os 快照。聊天状态存于 metadata 的 `world_os_characters.states`。改名和排序不改变角色 ID；删除目录条目会停止注入，其他角色关系描述中的旧名字不会自动改写。

## 状态快照

打开 **world os → 状态快照 → 导出当前快照**。包含：

- world os 总开关及楼层记忆、状态接口配置；所有已配置角色卡的日历规则、节日、角色设定、阶段、基础状态、权限、上传头像、CG、角色数字 ID、默认状态模板，以及聊天 CG 显示范围和角色查询清洗规则。

- 勾选后可包含已保存在宿主设置中的 API 密钥；默认不导出密钥，仅会话密钥不会进入文件。

快照不包含宿主聊天原文、其他聊天的状态、世界书或可重建的向量缓存。它是 world os 当前工作状态的备份，不代替宿主完整数据备份。导入最多 32 MB 的 JSON 文件后先显示范围和数量，点击“恢复所选快照”才覆盖状态。角色卡必须一致；恢复到同卡另一聊天需明确勾选选项。其他插件 metadata 与聊天原文保持原样，没有导出的密钥保留本机现有值。

Android 使用 TauriTavern 原生导出并等待写入完成；普通浏览器使用文件下载。导入通过标准文件选择器读取，不依赖电脑文件路径。

## 使用日历

1. 打开角色的一段聊天，点击 **world os → 日历**。
2. 展开「日历规则」，填写日历名、月份数与天数数组并保存。例如月份数填 3，数组填 `[30,31,28]`，即一年 3 个月，依次为 30、31、28 天。
3. 在「设置本聊天的当前日期」中填写年、月、日。新聊天默认从 1 年 1 月 1 日开始；这一日期不影响同卡其他聊天。
4. 点击上方某个日期，填写节日名和介绍／设定提示词。勾选「每年重复」表示每年此月此日触发；取消勾选后还需要填写指定年份。可在节日列表编辑或删除。
5. 聊天时点击输入框上方的「推进时间」，填写过去几天，检查预览并选择「推进并填入输入框」。

例如原输入为“我推开窗，望向街道。”，推进 3 天后到达星河历 128 年 8 月 15 日的团圆节，输入框变为：

```text
3天过后，星河历128年8月15日
团圆节
我推开窗，望向街道。
```

留空日历名时，首行为 `3天过后，128年8月15日`。同日多个节日的名称用顿号连接；只有推进结束当天的节日被注入，途中经过的节日不会一起加入。当前日期停留在节日当天时，后续生成仍会包含当天设定，直至日期改变或日历被关闭。

0.6.0 起，节日设定在 World Info 后末尾的格式如下，首尾各留空行；同日多个节日各用自己的名称作为标签：

~~~text

<团圆节>
家人相聚，城中挂起花灯。
</团圆节>

~~~

每年使用固定的天数数组，不自动套用公历闰年、农历、时区或现实节日计算。传统节日也需要按你采用的历法自行标记。支持 1～1000 个月，每月 1～1000000 天；超长月份的日期网格分页显示，日期运算在安全整数范围内执行。

规则存于宿主扩展设置的 `world_os_calendar.cards`，以角色头像文件名（群聊则用群 ID）区分；这不会改写角色卡文件，单独导出角色卡不会自动包含日历规则。当前日期存于聊天 metadata 的 `world_os_calendar.date`，随聊天保存。修改月长后若其他聊天的旧日期已不存在，打开该聊天后需要重新选择有效日期，插件不会悄悄截断或挪动日期。

注入接口核对来源：[SillyTavern 世界书扫描](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/world-info.js)、[TauriTavern 2.3.0 世界书扫描](https://github.com/Darkatse/TauriTavern/blob/v2.3.0/src/scripts/world-info.js)。使用 `WORLDINFO_ENTRIES_LOADED` 和最终 `WORLDINFO_SCAN_DONE`，在宿主组装 worldInfoAfter 前追加当天内容。聊天预设关闭该区域、文本模板省略 `{{wiAfter}}`，或 Agent 配置排除世界书时，该区域不会进入最终请求。

## 楼层定义与三段注入

**一条模型回复，加上它前面尚未归属其他回复的用户消息，算一楼。**

- 连续多条用户消息归入下一条模型回复。
- 没有前置用户消息的开场白也算一楼；群聊中每条可见模型回复分别算一楼。
- 尚未得到回复的尾部用户消息始终保留，不占 N、M、K。
- 隐藏系统消息不计楼层；宿主允许进入提示词的工具记录跟随所属楼层。
- 插件楼号从 1 开始，与 SillyTavern 按单条消息编号的楼号不同。

以已有 100 楼、N=8、M=20、K=5 为例：

| 区域 | 楼层 | 处理 |
| --- | --- | --- |
| 最近原文 | 93～100 | 整楼保留，包含用户消息和模型回复 |
| 中间总结 | 73～92 | 保留每楼用户消息，将模型回复换成总结 |
| 更早候选 | 1～72 | 关键词优先、向量补足；最多召回 5 楼的用户消息与模型总结 |

发送顺序为：

1. 更早候选区选中的楼层，逐楼注入「用户消息 → 模型总结」，按原时间顺序排列。
2. 中间 M 楼同样逐楼注入「用户消息 → 模型总结」，按楼层顺序排列。
3. 最近 N 楼的完整原文。
4. 当前尚未得到回复的用户消息。

三段互不重叠。同一楼有多条用户消息时全部按原顺序保留，包含原有附件；无前置用户消息的开场白不凭空添加用户消息。没有被召回的旧楼层不注入。

总结正文前的标记为 [历史召回 · 第 N 楼] 或 [近期召回 · 第 N 楼]，不加入角色名。宿主用于区分发言者的消息角色与 name 字段仍按正常消息格式保留。

「最近 N 楼原文不动」指本插件保留宿主传入的这些消息及其附加数据；宿主自身的提示词正则、附件处理等仍按宿主设置执行。插件不改写聊天消息原文，仅替换本次生成使用的消息数组。

特殊情况：

- 总楼数不足 N 时保留所有楼层；N、M、K 都允许为 0。
- 续写模式即使 N=0，也保留正在续写的最后一楼。
- 生成新的 swipe 时，待重生成的回复不进入候选区，其前面的用户消息作为当前待回复消息保留。
- 中间 M 楼缺少总结时，默认保留该整楼原文；也可设置为保留用户消息、只略过模型回复。
- 更早候选区中没有总结的楼层不参与召回。
- 命中结果不足 K 时，不插入无关楼层。
- 后台 quiet/impersonate 请求不进行上下文压缩。

## 正则：先清洗，再提取

每条模型回复的处理流程为：

原回复副本 → 按顺序执行清洗规则 → 执行总结获取正则 → 取指定捕获组 → 保存总结。

清洗不改动聊天里的原回复，也不清洗最近 N 楼要保留的原文。

默认清洗正则：

~~~regex
<(thinking|think)\b[^>]*>[\s\S]*?<\/\1\s*>
~~~

flags 为 gi，替换内容为空字符串。

默认总结获取正则：

~~~regex
<summary\b[^>]*>([\s\S]*?)<\/summary\s*>
~~~

flags 为 gi，捕获组为 1。

例如：

~~~xml
<thinking>
这里的思考内容不要进入总结。
<summary>思考中的伪总结也不要提取。</summary>
</thinking>
<content>苏岚交出了星钥，约定明天在北门会合。</content>
<summary>苏岚已交出星钥；双方约定次日北门会合。</summary>
~~~

最终保存：

> 苏岚已交出星钥；双方约定次日北门会合。

如果预设使用 memory 等其他标签，修改获取正则即可。命名捕获组示例：

~~~regex
<memory\b[^>]*>(?<memo>[\s\S]*?)<\/memory\s*>
~~~

捕获组填写 memo。

可添加多条清洗规则，启用/禁用、删除并用上下箭头排序。支持裸正则加 flags，以及 /pattern/flags 写法；后一种写法以尾部 flags 为准。替换支持 JavaScript 的 $1、$2、$<name> 等语法。

获取规则遍历全部匹配，把指定捕获组的非空结果用空行连接。捕获组 0 代表完整匹配；分组不存在或未匹配时不生成总结。

默认只清理 thinking/think，不移除 content：如果总结嵌在 content 中，删除整个 content 会连总结一起删除。「测试当前正则」可用尚未保存的规则查看清洗与提取结果。

匹配在独立 Worker 中执行，超时会终止 Worker 并停止本次注入。默认每批最多 24 条、每批超时 2.5 秒。处理超长消息时可简化正则。

## 关键词优先召回

查询从**最新一条用户消息（第 1 条）**向上取到**第 D 条用户消息**，包含两端的用户消息和它们之间的所有模型回复，D 默认 2。该范围按用户消息计数，与按模型回复计算的 N/M/K 楼层范围分开。

例如原对话为：

`用户 A → 模型 A → 用户 B → 模型 B → 最新用户 C`

- D=1：只使用「用户 C」。
- D=2：使用「用户 B → 模型 B → 用户 C」。
- D=3：使用上面整个区间。
- 连续多条用户消息各自计数；区间内有多条模型回复时全部纳入。
- 用户消息不足 D 条时，从最早的用户消息开始；无用户消息则不召回。
- 没有待回复消息时，区间仍截止于最新用户消息，不加入它之后的模型回复。
- D=0 保留原有选项：只使用当前尚未得到回复的用户消息。

查询执行同样的清洗规则，并移除总结正则的完整匹配；关键词和向量召回共用这个查询。默认 thinking 和 summary 内容不参与查询，模型正文里的词可以触发召回。

仅已保存到「逐楼总结与关键词」中的触发词参与匹配，可以手动输入或由 AI 生成：

- 关键词非空：与查询文本直接匹配；任意一个词命中，该楼就进入关键词召回候选，手动和 AI 生成的词使用同一套逻辑。
- 关键词为空：不匹配总结正文、不自动分词，也不根据搜索结果生成关键词。
- 关键词未命中或没有设置词的楼层，在关键词召回不足 K 且向量开关打开时，一起进入向量候选。
- 关键词已填满 K 时，不再为剩余楼层发起向量请求。
- 关闭向量时，未命中或未设置关键词的旧楼层不召回。
- 只用英文逗号 `,` 分隔多个手动词；每个词的首尾空格不参与匹配。中文逗号、顿号、分号等是关键词的一部分。
- `15,12` 可以由 `15` 或 `12` 触发；`12，12` 要匹配包含该中文逗号的完整词，不会因为单独的 `12` 或 `12,12` 命中。
- 输入框保留原始标点和空格，输入后自动保存。英文忽略大小写并检查单词边界，中文支持片段匹配。
- 手动关键词可以是别名，不要求该词同时出现在总结正文里，但必须命中当前查询文本。

多个楼层命中时，按楼层号从高到低选择最近的 K 楼，与命中几个关键词无关；注入时恢复从旧到新的时间顺序。例如 K=3，命中第 8、15、24、31、40 楼，会选第 40、31、24 楼，最终按第 24、31、40 楼注入；不请求向量或重排。大小写与全角变体的重复词只显示一次。

0.1.1 起没有补充词表，也没有自动分词流程。旧设置中的词表会被忽略，保存设置时清理；原有逐楼手动词继续有效。

插件内的「搜索楼号、总结或关键词」独立于上下文召回。即使一楼没有触发关键词，也仍能通过它的总结内容或楼号搜索到；搜索框、大小写处理和分页保持原行为。

## 独立 Embedding 配置

填写连接信息、选择模型后保存：

| 设置 | 说明 |
| --- | --- |
| API 地址 | API 根地址，通常含 /v1；也支持完整 /embeddings 地址 |
| 模型 | 从自动拉取的下拉列表选择，也可手动填写 |
| API Key | 本地免密服务可以留空 |
| 每批条数 | 默认 16，不支持批量时改为 1 |
| 超时 | 每次请求默认 30 秒 |
| 相似度下限 | 默认 0.25，使用余弦相似度 |

### 拉取模型名称

完成 API 地址或密钥输入后，离开输入框会自动请求模型列表；也可以点击「拉取／刷新模型列表」。已有连接在首次展开接口设置时也会刷新列表。

- 使用当前表单里的地址和密钥，不要求先保存，不要求先填写模型名。
- 请求 GET /models；填写完整 /embeddings 地址时会自动推导同级 /models 地址。
- 列表读取标准兼容响应的 data[].id，去重后显示在下拉框中。
- 选择模型后会填入模型输入框，点击「保存设置」后用于实际召回。
- 列表中可能包含聊天模型，请选择支持 Embedding 的模型；不按名字强行过滤，以支持名称不含 embedding 的服务商自定义模型。
- 服务不提供模型列表、返回空列表或请求失败时，可以继续手动填写模型名。
- 修改地址或密钥会取消旧列表请求，迟到的响应不会覆盖新列表；拉取失败也不会清空已经手动填写的模型名。

向量请求为 POST /embeddings，包含 model、input 数组、encoding_format: "float"。响应需有 data 数组，每项包含 index 和 embedding。保存后点击「测试已保存的接口」检查向量连接。

召回顺序严格为：

1. 完成关键词匹配。
2. 已达到 K 时，不发送 Embedding 请求。
3. 不足 K 时，只对**更早候选区中未匹配关键词的楼层**进行向量检索。
4. 首次使用的总结分批向量化，相同内容、接口和模型的向量复用缓存。
5. 查询向量化，按余弦相似度筛选，低于阈值的楼层不参与。
6. 未开启重排时，直接按向量相似度选取剩余名额；开启时，从向量候选池交给重排模型选择。
7. 与关键词结果合并后，按原楼层顺序注入，不重复占用名额。

「建立／更新本聊天向量」可提前向量化所有有总结的楼层，并清理该聊天的旧缓存键。自动召回按实际需要增量建立候选总结的向量。即使磁盘中还有过期缓存，检索也只读取当前楼层及当前总结的键，旧内容不会重新进入上下文。

接口失败、超时、响应异常或缓存维数不匹配时，保留关键词召回结果并显示原因。停止生成、切换聊天或改变消息时会取消未完成请求。

## 可选 Rerank 配置

在「④ 可选 Rerank 重排」中填写并保存：

| 设置 | 说明 |
| --- | --- |

### 重排模型列表

填写当前表单中的重排地址与密钥后，离开输入框会自动拉取列表，也可点击「拉取／刷新模型列表」，无需先保存。从完整 /rerank 地址推导同级 /models，保留原版本前缀，例如 /v2/rerank 对应 /v2/models。

三套模型列表各自使用自己的地址与密钥；切换地址会取消旧请求，迟到结果不会覆盖新列表。服务不提供兼容的 GET /models，或列表不区分聊天／重排模型时，可继续手动填写准确模型名。并非所有直接提供 Rerank 的服务都有该列表接口。

支持 [Cohere Rerank](https://docs.cohere.com/reference/rerank) 与 [Jina Reranker](https://jina.ai/reranker/) 兼容格式：

- POST /rerank，请求包含 `model`、`query`、`documents`（总结字符串数组）、`top_n`（剩余名额）。
- 响应为 `results` 数组，每项包含对应候选的 `index` 和 `relevance_score`。
- 地址的版本由所用服务决定，例如 Cohere 官方地址为 `https://api.cohere.com/v2/rerank`，Jina 官方地址为 `https://api.jina.ai/v1/rerank`。其他代理或本地服务按它们提供的地址填写。
- 保存后点击「测试已保存的重排接口」验证响应。接口是否支持浏览器 CORS 仍取决于实际服务。

关键词已经达到 K 时，不请求 Embedding 或 Rerank。关键词不足时，先对未命中的旧楼总结做向量筛选；候选池内符合相似度下限的总结多于剩余名额，才请求重排。若所有候选都能入选，则跳过这次额外请求。

重排按相关度取剩余名额，最终仍与关键词结果一起按原楼层顺序注入。向量相似度和重排相关度分别显示，原有向量阈值不会被误用为重排阈值。重排失败、超时或返回无效索引时，显示原因并使用原向量顺序，保留已有关键词结果；主动取消时终止本次操作，不提交部分结果。

重排增加一次服务请求，候选池越大，发送的总结越多；是否改善召回取决于模型及对话内容。不需要时关闭即可。

## AI 一键设置关键词

在「⑤ AI 一键设置关键词」填写独立的 Chat Completions 连接，保存后运行。此功能不使用聊天窗口当前的生成预设，也不复用 Embedding 或 Rerank 密钥。

| 设置 | 默认值／说明 |
| --- | --- |
| API 地址 | 根地址，或完整 /chat/completions 地址；需要浏览器 CORS |
| 模型 | 自动拉取下拉选择，也可手动填写；选择能遵循指令并输出 JSON 的聊天模型 |
| 每批楼数 | 8，允许 1～100 |
| 每楼关键词上限 | 8，允许 1～30 |
| temperature / top_p | 0.2 / 0.9，可按模型建议调整 |
| 最大输出 token | 每批 2048，可设 128～32768 |
| 请求超时 | 每批 60 秒，可设 1～300 秒；是最长等待时间，不是主动延迟 |
| 思考模式 | 自动：硅基流动官方地址 + Qwen3-8B 关闭思考，其他连接保持原参数 |
| 排除用户 | 默认开启；清除字面量 {{user}} 和当前用户名的完整关键词 |
| AI 关键词清洗正则 | 默认空列表；在此功能的折叠面板内添加，与聊天清洗规则独立 |
| JSON 输出模式 | 默认关闭；开启时发送 response_format: {"type":"json_object"} |
| 回复后自动提取 | 默认关闭，启用后在楼层记忆开关开启时生效 |

### 处理已有长聊天

1. 设置并保存 AI 关键词的地址、密钥、模型和预设；可先点「测试已保存的关键词接口」，测试使用一条示例总结，不写入聊天。
2. 选择写入方式：默认「只补空关键词，保留当前非空关键词」；需要全部重做时选「重新生成全部，覆盖现有关键词」。
3. 点击「AI 一键设置本聊天关键词」。自动同步总结，然后分批处理当前聊天的所有非空总结，包含 N/M/K 区域以外的楼层。
4. 每批成功后立即保存并显示进度。完成后可在逐楼卡片直接编辑关键词，也可立即参与现有关键词召回。

「只补空关键词」只查看当前有效关键词是否为空，空白输入也算空；不因为该楼以前设置过、手动删除过，或 AI 曾返回空数组而跳过。有总结但关键词为空，就进入本次批量处理；当前非空的手动／AI 关键词均保留。

输入只有本批的楼号、角色名和有效总结，人工覆盖过的总结优先。不会把整段原始聊天一次发给模型。API 失败或输出缺楼／重复楼号时不写入错误的那一批，此前已完成的批次保留；可调整设置后再次运行。

「取消当前操作」会终止进行中的请求，不回滚已经保存的批次。手动改词、改总结、改变消息或切换聊天，会取消旧请求结果，避免覆盖新内容。AI 返回的关键词遵循同一套英文逗号分隔规则，中文逗号仍是词的一部分。

### 编辑提示词预设

展开「关键词提示词预设」，可增删消息、上下移动，并分别选择 system / user / assistant 的 role。消息按界面顺序发给模型，支持自定义示例或要求。修改后点击「保存设置」生效；「恢复内置提示词」只恢复编辑器内容，保存后生效。

可用占位符：

| 占位符 | 内容 |
| --- | --- |
| {{summaries}} | 本批楼号、角色名与总结组成的 JSON 数组；至少一条预设消息必须含此项 |
| {{max_keywords}} | 每楼关键词上限 |
| {{char}} | 当前角色名 |
| {{user}} | 当前用户名 |

内置提示词优先从每楼总结中提取明确出现的人名、地名，其次组织、独特物品与事件名；避免泛词，不要求补造不存在的名字。自定义预设仍需要求以下返回结构，使用输入中的实际楼号：

~~~json
{"items":[{"floor":1,"keywords":["示例角色甲","青石镇"]},{"floor":2,"keywords":[]}]}
~~~

同时兼容模型直接返回数组，例如 `[{"floor":1,"keywords":["示例角色甲","青石镇"]},{"floor":2,"keywords":[]}]`。两种格式使用相同校验，结果顺序可以不同，但本批每个实际楼号必须出现且只出现一次，不能把不连续楼号改为 1、2、3。没有合适关键词也应保留该楼，填写空数组。

### AI 返回 JSON 的自动修复

解析按「去掉明确的包裹内容 → 修复可确定的格式错误 → 验证楼层与字段 → 执行关键词清洗 → 保存本批」进行。修复在浏览器本地完成，没有额外模型请求。

| 常见返回问题 | 处理 |
| --- | --- |
| 正文末尾多一个或多个 `}`、`]` | 识别字符串与容器边界，移除完整正文后的多余闭括号 |
| Markdown 代码围栏、前后说明、已结束的思考段 | 提取其中明确的 JSON 正文；不会从未结束的思考段取结果 |
| 对象／数组最后一项后的尾逗号 | 删除尾逗号 |
| 单引号、弯引号、未加引号的字段名 | 按字符串和字段边界读取，保留词内原字符 |
| 字符串外用了中文／全角冒号、逗号、括号 | 按结构标点处理；关键词内的 `12，12` 仍是一个词 |
| 完整字段或数组项之间漏逗号 | 边界明确时补上分隔符 |
| items、floor、keywords 字段后漏冒号 | 对应值完整且可识别时补上冒号 |
| 末尾漏了闭括号 | 仅在已经读到完整值时补全容器，不补关键词内容或楼层 |
| JSON 又被编码为字符串、或整体额外转义一次 | 有限层数地解开编码，保留词内的有效转义和路径字符 |
| 单楼返回一个对象、或逐行返回楼层对象 | 统一为楼层结果列表，再校验全部实际楼号 |
| floor 是纯数字字符串 | 转为整数后核对本批楼号 |
| keywords 返回字符串 | 按英文逗号转为关键词数组；中文逗号保持字面含义 |
| JSON 中有行注释或块注释 | 仅移除字符串以外、边界完整的注释 |

接口返回后，「最近请求」会显示本次用到的 JSON 兼容处理；完整合法结果无需修复。字段里的数字不会被猜成名字，未知字段名也不会自动改写成 floor 或 keywords。

以下情况仍拒绝本批写入：未闭合或被截断的关键词字符串、逗号后缺失内容、重复对象字段、存在多份无法确定取舍的结果、缺楼／多楼／未知楼号／重复楼号，以及非字符串关键词。服务明确返回 `finish_reason: "length"` 时仍按截断处理。此前成功保存的批次保留。

格式错误、无法可靠修复与数量不一致分别提示；数量不一致时列出本批目标楼号和实际返回条数。解析设置了响应长度、嵌套深度和条目数上限，防止异常输出长时间占用界面。

### 清洗 AI 返回的关键词

展开「AI 返回关键词的清洗规则」。默认勾选「排除 {{user}} 和当前用户名」：请求时提醒模型不要提取用户本人；返回后再按完整关键词过滤，即使模型没遵守提示也不会保存这些词。过滤发生在每楼数量上限之前，用户名不会占用有效关键词名额；例如用户名为「旅行者」时不会误删「旅行者村」。

这里的自定义规则逐个作用于 AI 返回的词，按列表顺序替换；支持匹配正则、flags、替换内容、启用／禁用和排序。与聊天清洗正则分开，不会在 AI 返回关键词时再次执行整段聊天的规则。

例如去掉「我、你、用户、玩家、主角」这些泛词：

~~~regex
^(?:我|你|用户|玩家|主角)$
~~~

替换为留空。也可用 `^人物[:：]` 删除名称前的「人物：」前缀。清洗为空的词被删除，剩余词去重后保存。英文逗号仍分隔多个词，中文逗号仍是关键词的一部分。

这些规则应用于之后的接口测试、批量提取和自动提取，不主动修改已经保存的词或手动输入。需要清理已有 AI 关键词时可选全量重做。复杂正则在独立 Worker 执行，超时会终止该批且不写入半成品。

### 硅基流动 Qwen3-8B 与思考设置

「自动」在 API 地址为 `api.siliconflow.cn` 或 `api.siliconflow.com`、模型为 Qwen3-8B（含服务前缀）时，自动补充顶层 `enable_thinking: false`。已有附加参数明确指定 `enable_thinking` 时，自动模式尊重该值。

「关闭」始终发送顶层 `enable_thinking: false`，可用于支持同一参数的中转；「使用服务默认／附加参数」不自动加开关。修改后保存设置生效。

对于硅基流动，也可以直接把「附加请求参数」设成：

~~~json
{"enable_thinking":false}
~~~

硅基流动使用顶层参数，依据其 [Chat Completions 接口文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)。`chat_template_kwargs: {"enable_thinking":false}` 是部分本地／vLLM 服务使用的写法，不应直接当作硅基流动参数使用。

已有界面选项（model、messages、stream、temperature、top_p、max_tokens、response_format）不能在附加参数中重复覆盖。只添加所用服务支持的参数；该项不是 SillyTavern 整套预设文件的导入器。

### 每次回复后自动提取

勾选自动提取并保存后，插件等待回复完成与正则总结同步，再处理本次新产生的楼层。群聊一轮有多条回复时分别对应所属总结；重复收到同楼事件不会重复请求。没有总结的楼层直接跳过，打开已有聊天不会自行批量付费处理历史。

自动结果使用已有逐楼关键词字段参与匹配。当前非空关键词会保留；手动清空后的楼层在后续被独立的新回复事件选中时可重新补词，不会被正在运行的旧请求覆盖。

只有自动模式会记住「该总结已由 AI 处理但没有关键词」：同一总结的重复事件不会反复请求空结果。显式点击一键「只补空关键词」仍会重试这些空楼层。自动请求失败时显示原因，不无限重试。

自动提取不在发送上下文的召回步骤中调用；后续生成开始时会取消未完成的后台任务，已经保存的词可以用于下次召回。

### 小模型选择与开销

对于简短总结中的人名、地名提取，7B～8B 指令模型是值得先试的选择；这是根据任务范围作出的建议，并非本项目已测得的准确率。官方型号可参考 [Qwen2-7B-Instruct](https://huggingface.co/Qwen/Qwen2-7B-Instruct) 和 [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)。

- 可先用 Qwen2-7B-Instruct 配合默认每批 8 楼、每楼最多 8 词，抽查 20～30 楼的人名与地名，观察漏词、误词和楼号错配。
- Qwen3-8B 支持非思考模式；该任务可以先试关闭思考。具体关闭参数由服务决定。官方对非思考模式建议 temperature=0.7、top_p=0.8，可在界面设置，不必套用插件的通用默认采样值。
- 小模型输出格式不稳定时，优先减少每批楼数、使用服务支持的 JSON 模式，再判断是否需要更大模型。
- 对硅基流动 Qwen3-8B，附加参数为空只代表插件没有显式关闭思考，提示词中的「不要输出思考」不能替代接口开关；先使用上面的关闭思考设置，再观察耗时。3 楼也可能因为推理或服务端排队而慢，不能只根据楼数判定。
- 最大输出 token 用于控制回复长度；硅基流动文档说明该上限不包含思考 token，因此单独降低它并不能限制思考过程。
- 成本还取决于服务价格、输入输出 token 和思考开关。批量时只发送总结，日常只处理新回复，可减少重复输入；本项目没有用真实付费模型测量费用或实体提取质量。

### 查看慢请求的耗时

批量处理时状态栏每秒显示本批楼数与已等待秒数。每批结束或失败后，「最近请求」显示预设和总结的总字符数、接口往返时间、本地解析与正则清洗时间；接口提供 usage 时显示输入、输出和思考 token 数。未返回的 token 字段不会伪装成 0。

接口往返包含网络、服务排队和模型生成，本插件的非流式接口不能进一步拆开这三项。如果已关闭思考后仍需近 100 秒，而本地解析清洗只有很短时间，应继续排查服务端耗时；增加超时只会允许等待更久，不会让模型更快。没有实际服务日志和测量前，不能把全部耗时归因于思考。

### 浏览器访问要求与密钥

这是纯前端扩展，Embedding、Rerank 和 AI 关键词请求直接发往各自所填服务：

- 服务需允许来自 SillyTavern 页面来源的 CORS 访问，模型列表使用 GET /models，向量化使用 POST /embeddings，重排使用 POST /rerank。
- HTTPS 页面通常不能直接访问普通 HTTP 接口。
- 三套密钥独立配置，默认只保存在当前标签页的 sessionStorage 和内存中。
- 只有勾选「将密钥明文保存到 SillyTavern 设置」时才会写入宿主设置文件。
- 发给 Embedding 服务的是候选总结和查询文本；发给 Rerank 服务的是经过向量筛选的候选总结和同一查询文本；AI 关键词服务只收到当前批次总结、楼号及自定义预设内容。
- 不复用 SillyTavern 的向量来源、聊天 API Key 或内置聊天向量索引。

服务不支持浏览器跨域时，需要在服务端允许该来源，或使用自己配置了 CORS 的兼容接口。

## 存储与逐楼编辑

- 总结保存在当前聊天的 chatMetadata.floor_summary_memory 中，随聊天元数据保存。
- 记录包含自动提取结果、楼号、内容标识，以及可选人工总结、关键词数组、关键词输入原文、手动／AI 来源及 AI 已处理总结的标记。
- 关键词输入后立即更新当前聊天并自动保存；保存进行中连续输入会合并后续保存，不会每次重绘输入框。总结草稿仍需点击「保存总结」。
- 向量保存在当前浏览器的 IndexedDB floor-memory-v1 中，不写入聊天 JSON。
- 向量键区分聊天、角色/群组、接口、模型、楼层内容和总结内容。
- 修改原文、前置用户消息或切换 swipe 后重新匹配对应楼层，旧记录不参与召回。
- 删除楼层后重新编号，内容不变楼层的人工覆盖会保留。
- 改变正则后重新提取，但保留当前消息内容对应的人工覆盖。
- 「恢复正则提取」仅移除该楼人工总结覆盖，关键词及其输入格式保持不变。
- 旧版本已存储的关键词数组保持原匹配含义；旧显示分隔符统一用英文逗号显示。旧版已被拆开的词无法自动推断为一个带中文逗号的词，如需合并可在新输入框重新输入。
- 人工覆盖绑定当前这版消息内容，不作为所有历史 swipe 的永久笔记保存；切换或改写消息后应检查该楼总结。

「导出总结 JSON」导出当前总结用于查看或留档，不包含密钥与向量。单独导出的总结文件仍不用于导入；需要恢复时，请使用 0.6.0 新增的「状态快照」导出与导入。

更换浏览器或清理站点数据后需重建向量；已随聊天保存的总结不依赖本地向量缓存。IndexedDB 不可用时会提示并临时使用内存缓存。

「预览本次注入」使用已保存配置，展示各区域楼号、缺总结楼层、召回数量，以及每个结果的命中词、向量相似度或重排相关度；有服务降级时显示原因。最后追加「查询文本:」及用于本次匹配的查询全文，到查询文本结束，不追加最终组装的聊天内容。开启向量或重排时，预览可能请求相应接口；预览本身不会调用 AI 关键词接口。

## 其他扩展与兼容性

本扩展使用 generate_interceptor，加载顺序为 1，通过宿主上下文 API 保存设置与聊天元数据。

建议关闭其他扩展的聊天历史删除、聊天向量替换或总结压缩功能，避免重复压缩同一段历史。若进入本扩展前上下文已被删改且无法可靠对应原聊天，会停止生成并提示。后续扩展仍可能改变最终提示词，首次使用时应检查宿主实际发送的提示词。

开发时对照了 SillyTavern release 分支 1.19.0 的上下文和生成流程。清单最低版本为 1.13.0；未在 1.13～1.19 的完整版本矩阵中逐个验证。TauriTavern 对照了 v2.3.0 的真实源码契约，并在 Chromium 中模拟其资源路径、宿主启动时序、Android 屏幕、工具投影和原生保存接口。当前工作区没有连接 Android 真机，也没有真实 Embedding / Rerank / AI 关键词 / 角色状态接口凭据，因此这些检查不等于 Android APK 真机验收；所选服务的 CORS/模型兼容性仍需在实际安装环境验证。
